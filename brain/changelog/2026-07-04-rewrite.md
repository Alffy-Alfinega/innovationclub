## Addendum 2 — Vercel build fix + DB migration path
**Vercel failure root cause:** `prisma generate` never ran on Vercel (fresh
node_modules, no generated client → PrismaClient untyped → implicit-any
typecheck failure on `students.map`). Fixed: `build` script is now
`prisma generate && next build`, plus a `postinstall` generate. Package
renamed scaffold-tmp → innovationclub.

**Same-Neon-DB migration path (ORDER MATTERS — legacy `students` table
already exists there with the old shape; blind `prisma migrate` collides
or resets):**
1. `psql "$DATABASE_URL" -f scripts/00-preserve-legacy.sql` — renames
   `students` → `students_legacy` (data preserved)
2. `npx prisma migrate dev --name init` — creates the new schema
3. `SUPER_ADMIN_EMAIL=... SUPER_ADMIN_PASSWORD=... npx tsx scripts/seed.ts`
   — Makindye school + super admin (idempotent, min 12-char password enforced,
   credentials from env only, never hardcoded)
4. `npx tsx scripts/migrate-legacy-students.ts` — DRY RUN, prints mapping
5. `APPLY=1 npx tsx scripts/migrate-legacy-students.ts` — writes; preserves
   original registration dates; idempotent; never drops students_legacy
6. Verify counts in /dashboard/school, then drop students_legacy manually

## Addendum 3 — Vercel deploy fix #2 (framework preset)
Second deploy failure: Next.js build succeeded fully, then Vercel errored
"No entrypoint found (app.js/index.js/server.js)". Root cause confirmed via
Vercel API: project `innovationclub` (prj_IgR4utCO8PJEGxpfFJidCW0S4yO2) still
had `framework: "express"` from the old app — Vercel was treating the output
as a Node server and hunting for app.js. Fixed with `vercel.json` setting
`framework: "nextjs"`, which overrides the dashboard preset from the repo.
Lesson: the wipe cleared the repo, not the deployment platform's memory of it.
