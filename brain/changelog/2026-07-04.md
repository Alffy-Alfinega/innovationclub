# 2026-07-04 — Interim security patch (pre-rewrite)

> **Context:** Full Next.js + react-babylonjs multi-dashboard rewrite is planned but not started.
> Live site (`innovate.alfinega.com`) has real registrants and cannot go dark or stay open
> while unprotected in the meantime. This patch closes the exploitable gaps in the
> current Express app without touching architecture, styling, or scope.

## Changes

1. **CSRF protection** — double-submit cookie pattern (`csrf_token` signed httpOnly
   cookie + `_csrf` hidden form field). No session store needed. Rejects mismatched/
   missing tokens with a fresh token reissued so the user can just resubmit.
2. **Rate limiting** — `/register` POST capped at 10 submissions per IP per 15 min.
   Read routes unaffected.
3. **Security headers** — `helmet()` applied globally. CSP left disabled for now
   pending an inventory of all external font/script origins (Google Fonts CDN etc.) —
   enabling it blind would break the page. Flagged as a follow-up.
4. **Server-side input validation** — email and phone now checked against regex on
   the backend, not just HTML5 `type=` attributes (which do nothing server-side).
5. **Fixed the `iscc` schema-drift bug** — the checkbox was removed from `register.ejs`
   in a prior commit but `db.js`/`app.js` still had the column and were silently
   inserting `false` forever. Column is kept (existing rows untouched) but no longer
   written to, and annotated in `db.js` so it doesn't get "rediscovered" as a bug again.
6. **Minimal admin view** (`/admin`) — env-credential-gated (basic auth via
   `ADMIN_USER`/`ADMIN_PASSWORD`), lists the 500 most recent registrants. This is
   explicitly interim — the real role-based admin/school-admin/mentor/student
   dashboards are scoped for the Next.js rewrite, not built here.
7. **Generic error handler** — raw Express error pages no longer reach the public;
   errors are logged server-side, users see a plain message.

## Explicitly NOT done here (deferred to the rewrite)

- Multi-school architecture (`schoolName` hardcoded fallback still present)
- DDL-on-startup (`CREATE TABLE IF NOT EXISTS` in `db.js` — still runs every boot)
- Any of the 5 planned role tiers (super admin, school admin, mentor, student/parent,
  break-glass) — `/admin` above is a stopgap, not the real thing
- Email confirmation to registrants
- Automated tests

## Deploy checklist for whoever ships this

1. `npm install` (adds `helmet`, `express-rate-limit`, `cookie-parser`, `express-basic-auth`)
2. Set `COOKIE_SECRET`, `ADMIN_USER`, `ADMIN_PASSWORD` in the host's env — see `.env.example`
3. Without those three vars, `/admin` stays disabled (logs a warning on boot, doesn't crash)
4. Verified locally: CSRF issuance (200), CSRF rejection without token (403),
   `/admin` without auth (401), `/admin` with auth (200/500 depending on DB reachability)
