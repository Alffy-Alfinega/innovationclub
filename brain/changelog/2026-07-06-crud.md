# 2026-07-06 — SUPER_ADMIN CRUD (users + schools)

Built per "give admins CRUD power, start with the superuser":

## Users (/dashboard/super/users — new route, sidebar link for SUPER_ADMIN + BREAK_GLASS)
- Create: name/email/role/school/initial password (12+ chars, bcrypt cost 12,
  duplicate-email rejected, role↔school pairing enforced server-side:
  school-scoped roles REQUIRE a school, cross-school roles must have none)
- Update: name/role/school inline per row + optional password reset
  (blank = unchanged); same pairing rules
- Deactivate/Reactivate instead of hard delete — AuditLog FKs to User and
  the break-glass accountability trail must survive; authorize() already
  blocks inactive logins so deactivation takes effect immediately
- Lockout rails (server-side, not just UI): cannot deactivate self;
  cannot deactivate OR demote the last active SUPER_ADMIN (with no
  PC/CLI, a locked-out platform would be unrecoverable for this user)
- Audit: USER_CREATE / USER_UPDATE / USER_DEACTIVATE / USER_REACTIVATE,
  never containing password material

## Schools (super dashboard, per-row Manage panel)
- Update: name (case-insensitive clash check) + address; **slug immutable**
  — /register resolves by slug, stated in the UI itself
- Delete: two-step confirm, HARD-blocked while school has any students or
  users (minors' records cannot be cascade-wiped behind one button);
  audit-logged SCHOOL_UPDATE / SCHOOL_DELETE
